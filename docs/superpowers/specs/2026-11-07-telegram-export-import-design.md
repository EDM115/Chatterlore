# Telegram export imports (JSON and HTML)
Status: owner-approved narrow extension implemented, verified and deployed (2026-11-07), see [the exact qualified acceptance](../../mixed-provider-acceptance-2026-11-07.md#telegram-desktop-json-and-html-import-extension).  
## Intent and constraints
Accept Telegram Desktop exports of an ordinary group, a whole forum or an individual forum topic, including HTML-only archives. The owner requested Both exports for verification and keeping the original files in Downloads. Existing JSON commands and limits remain compatible, do not execute exported JavaScript, fetch linked resources or alter the source archive.  
## Approaches
The proposed approach reuses the bounded message/embedding/write pipeline with format-specific readers. Prefer result.json when an export directory contains Both formats, otherwise parse messages.html and its validated same-directory pagination files using the Python standard library. This avoids a second persistence system and a new dependency. A separate HTML persistence path would duplicate source-fingerprint, auditing and idempotency logic. Automatic topic attribution from reply links is rejected because Telegram Desktop omits the reliable top-of-thread field, cross-topic replies and date-filtered exports can be ambiguous.  
## Scope contract
An explicit --thread-id imports a topic export into that exact topic, with mismatched explicit thread metadata rejected before provider calls or message writes. Without --thread-id, a whole-group archive imports into aggregate chat memory, not an inferred topic. Existing Scope hierarchy remains unchanged, a topic never contains aggregate rows. Warn clearly when a forum archive lacks per-message topic metadata and is imported at chat level. No implicit cross-topic routing from reply_to_message_id, service-row order, author names or file names. General live updates resolve to topic 1 rather than the aggregate scope, explicit this_chat/API chat queries remain aggregate.  
## Reader and command contract
Add an auto-detecting import-telegram CLI entry point that accepts a JSON/HTML file or export directory, keep import-telegram-json working and provide an explicit import-telegram-html alias. Normalize HTML into the existing message records, preserve Telegram message IDs, timestamps with timezone offsets, joined author labels, text, links, reply IDs and attachment labels. Do not invent numeric Telegram user IDs when HTML does not contain them. Ignore service rows and active content. Reject malformed exports, missing required dates/IDs, unsafe pagination paths, cycles and aggregate limit violations with actionable errors. Existing operator-directed historical import policy is unchanged.  
## Verification and completion
Write failing regressions before implementation. Prove JSON/HTML imports of the same archive are idempotent, topic targets remain isolated, aggregate queries contain the group, HTML scripts are never executed and linked resources are never fetched, and pagination/file/row limits remain bounded. Run the actual Both and individual-topic files against disposable databases with fake providers first, then complete bounded real-provider acceptance in the named test groups. Update command/setup/operations/testing documentation, the live evidence report and PLAN. DeepSeek, inference-server installation and unrelated permissions/privacy changes stay outside this extension.
