# Session and scoped-settings fixes
The owner approved stable session-bound CSRF tokens, explicit scoped-setting resets with correct parent values, and logout in desktop/mobile browsers only. The purpose is to keep multiple open tabs usable and make inheritance reversible without changing enrollment, provider routing, CI or Docker policy.  
## Approaches
Use a deterministic HMAC-derived CSRF token tied to the random session bearer, persist only its hash and retain active-session, same-origin and header validation. Per-read rotation causes cross-tab invalidation, plaintext persistence or a new encryption/schema boundary is unnecessary. Existing sessions adopt the stable token on their next session refresh, previously open tabs need one refresh after that transition. The shared feedback distinguishes `csrf_rejected` from actual scope-permission denial and asks for a refresh.  
Keep the existing nullable settings PATCH contract: an explicit null removes an override, omission leaves it unchanged. Show the complete effective parent map even when a field is overridden. Add per-field reset controls and submit null when an existing override is cleared. Preserve optimistic versions, authorization and audit events.  
Expose logout only for an authenticated browser session, revoke via the existing CSRF-protected endpoint and navigate to login after success. Show a safe error and retain the session on failure. The Mini App has no logout control.  
## Acceptance
Two tabs can refresh and mutate using the same session without invalidating each other's CSRF token. Different sessions have different tokens, wrong/revoked/expired sessions remain rejected, no plaintext session or CSRF token is stored. Chat resets restore global values, topic resets restore chat values and later parent updates flow through. Browser logout works in both navigation layouts and remains absent in Mini App navigation.
