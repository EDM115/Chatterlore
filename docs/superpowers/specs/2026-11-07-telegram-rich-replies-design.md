# Telegram rich replies, streaming and quiet command menus
Status: implemented and verified offline (648 passed/one credential-gated live skip on the final Python 3.14 source), not deployed or real-client accepted in this pass. Native execution followed the owner's earlier opt-out from routine plan-approval pauses.  
## Intent and boundaries
Render AI Markdown and structured application replies correctly in Telegram, show real generation progress where supported, and remove this app's automatically published slash-command list without removing any handler. Keep the existing provider selection, redaction, scoped retrieval, credential policy and safe telemetry boundaries. No schema/frontend migration, package graph upgrade, paid live call, deployment, privacy-mode change or BotFather reconfiguration is part of this pass. Declare the already-locked transitive markdown-it-py 4.2.0 as a direct dependency because safe Markdown parsing is now an application responsibility.  
## Approaches and selected implementation
Legacy MarkdownV2 alone fixes basic emphasis but cannot express the requested new rich structure and needs fragile escaping. Repeatedly editing ordinary messages everywhere misses Telegram's private animated drafts. Use the installed aiogram 3.31 rich-message types instead: safely parse model Markdown to the API's rich HTML input with markdown-it-py (raw HTML and image rules disabled), explicit literal rich blocks for application-owned replies, private rich drafts during real streamed generation and throttled updates of a single persisted rich reply in groups/topics. This preserves code literals without a hand-written Markdown sanitizer. Final replies persist complete content and source references, providers without a real streaming method return one completed answer rather than simulated token progress.  
## Delivery contract
The shared safe-answer boundary preserves destinations, business/thread/reply metadata, keyboards and document behavior. Plain dynamic values are never interpreted as model Markdown, multiline application output can use a heading and literal body blocks. Model Markdown supports ordinary headings, lists, tables, code and emphasis, raw HTML and media embedding syntax are neutralized so generated text cannot cause Telegram to fetch arbitrary remote media or create interactive controls. Bound rich payloads and split fallback text on Unicode-safe boundaries, preserve content rather than slicing answers at 3900 characters.  
On an explicit rich-format rejection or unsupported rich method, fall back once to a literal regular message (no parse mode and no link previews). Never send a second copy after an ambiguous network failure or rate limit, observe a returned retry-after before another progress update. Log only controlled error classification and method/scope identifiers, not rejected content or raw API exception text. Document captions remain literal.  
Owner clarification: split long responses logically, not at arbitrary source offsets. Preserve paragraphs, list items and table rows where possible, repeat table headers and continue ordered numbering, keep every code fragment literal and resolve references against the whole Markdown document. Split an individually oversized block only when required, prefer line/sentence/word boundaries before Unicode-safe forced cuts and degrade an indivisible oversized row/inline block to literal output instead of corrupting its Markdown. Group finalization and direct replies share this policy.  
## Streaming and cancellation contract
Add an optional asynchronous cumulative-text callback to the service/provider-operation path, not a second RAG implementation. OpenAI-compatible providers consume SSE inside the existing request/lease lifetime, preserve dialect parameters and input redaction, collect final token usage where supplied and always close streams. Never expose reasoning deltas. Before visible output the existing bounded retries/key rotation remain valid, after a text delta an interrupted stream must not silently restart/rotate or concatenate another answer. Presentation callback failures are not provider failures. Embedded/fake/custom providers without a streaming method stay compatible.  
After partial output, an unsuccessful stream retains explicit interruption state through provider execution and retrieval, final delivery acknowledges that no completed answer was produced rather than silently substituting the ordinary pre-output retrieval fallback. Usage retains a content-free interruption flag, partial prose is not persisted as a completed answer.  
Private drafts use a unique nonzero ID and are finalized with sendRichMessage because drafts expire. Support Telegram's Stop update only for the exact private chat/thread/draft that owns the active request, cancel the provider stream, persist content-free cancellation usage and show a stopped acknowledgement without preserving unfinished prose as a completed answer. Group progress uses one message and bounded edit cadence, does not call private-only draft APIs and finishes with the full authoritative answer/source references. Superseded and shutdown tasks release registry entries and provider streams, no process-global persistence or secret-bearing state is added.  
## Menu contract
Polling, webhook and optional connected development startup delete the default-language/default-scope command list previously published by this application, never republish it. Preserve manual command dispatch/help, the existing Main Mini App/menu button and owner-managed custom language/chat command scopes. Menu visibility is not authorization, all existing admin and scope guards remain. The Mini App covers routine administration but is not declared full command/CLI feature parity.
