## Lockfile and selected transitive boundaries

The initial staged `web/pnpm-lock.yaml` changes 2,267 added and 3,029 removed lines, so it is materially broader than the 15 direct declarations. Peer-context changes are not all separate version upgrades. The lock stays at format `9.0` and resolves Node `26.13.0`, Vite `8.3.6`, Nuxt CLI `4.0.3`, Nitro `2.13.6` and h3 `1.15.11`.  
The [Nuxt CLI v4 release](https://github.com/nuxt/cli/releases/tag/v4.0.0) changes dev-server process/terminal behavior and requires current supported Node versions, so `scripts/dev.mjs` process coordination needs its unit tests plus a real local start/stop smoke. The [Nitro 2.13.6 release](https://github.com/nitrojs/nitro/releases/tag/v2.13.6) deliberately prevents caching personalized/cookie-bearing responses and rejects proxy/redirect scope escapes, do not undo those protections to preserve old behavior. The [Vite 8.3.6 changelog](https://github.com/vitejs/vite/blob/v8.3.6/packages/vite/CHANGELOG.md) covers the new minor/patch graph, including resolver, build/CSS, HMR and file-serving security fixes.  
This document does not claim that every changed transitive package has an individually audited changelog. It reviews the complete changed direct manifest surface and the notable framework/runtime boundaries above. Native platform packages, optional dependencies, integrity fields, peer duplication and any additional lock-only package changes still require graph validation and a fresh frozen install, source review alone cannot establish their runtime compatibility.

## Follow-up Runtime Policy And Peer Evidence

The owner subsequently requested Node major-only declarations, so `devEngines.runtime.version` is now `26` and both frontend image stages use `node:26-bookworm-slim`. Regenerating the runtime lock changed only its specifier from `runtime:^26.13.0` to `runtime:26`, the resolved runtime remains 26.13.0. The image uses pnpm's standalone installer following the provided [spendly example](https://github.com/EDM115/spendly/blob/master/Dockerfile), not Corepack or npm-global bootstrap.  
`pnpm peers check` reports one explicit upstream metadata mismatch: unchanged `openapi-typescript@7.13.0` declares TypeScript `^5.x`, while this project intentionally uses the `@typescript/typescript6@6.0.2` alias. Frozen installation, generation and typechecking are executable compatibility checks, not a claim that upstream officially supports TypeScript 6. The warning is retained, no broad peer waiver or compiler downgrade was added.

## Concrete adaptation and acceptance checklist

- Required: point the setup action at `web/`, align the frontend Docker runtime/bootstrap with Node 26 and pnpm 11.28.11, preserve managed-runtime lock resolution, and keep current human-facing setup/deployment/testing descriptions synchronized
- Required verification: frozen install, managed Node version, target Oxfmt check, type-aware Oxlint, Nuxt typecheck, all unit/component tests, generated OpenAPI drift, SSR production build, generated-asset privacy scan and nonce-aware SSR smoke
- Required browser verification: matching Playwright Chromium plus both existing desktop/mobile projects, with particular attention to authentication/step-up, redirects, accessible names, device-screen behavior and expiry timers
- Required environment verification: frontend image build/start/health and coordinated local dev-proxy start/stop, local source or unit-test success is not Docker or hosted-CI success
- Preserve secure defaults: no broad happy-dom network-loading opt-in, no widening of personalized response caching, no exposed production exception details, no blanket disabled mock clearing or lint warnings
- Retain uncertainty: DefinitelyTyped per-version source mapping is partial, every-transitive changelog coverage is not claimed, and deployment/live Telegram/OIDC acceptance is outside this source audit
